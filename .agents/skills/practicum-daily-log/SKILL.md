# 每日实习日志

将当天教学材料和真实操作证据整理成一份可交付的日志，按日期更新同一份 Word 主文档。此 skill 放在仓库中供组员分发，生成日志本身与项目开发无关。

## 执行边界

- 不触发 `repository-development-workflow`，不运行 Git / `gh` 检查或同步，不创建分支、worktree、Issue、PR，不运行仓库 CI；从仓库启动也不改变这个边界。
- 临时脚本、样例、编译产物、日志、截图、Markdown 留底和文档渲染均放在执行环境的 `/tmp/practicum-daily-log/<task>/`，WSL 任务放 WSL 内。显式设置工作目录和输出路径，不写仓库的 `src/`、`docs/` 或构建目录。
- 更新用户指定的日志文件属于本任务，不应因此创建 worktree。默认在上述任务目录生成交付物；仅用户明确指定时才复制到其他位置或仓库。检查文件中是否含无关信息或敏感内容，默认保留本次临时目录供复核。
- 若用户同时要求修改项目代码或 skill 源文件，仅该部分进入仓库开发流程，日志部分继续独立处理。

## 材料与身份

复用会话中已给出的日期、材料、个人信息和主文档路径。输入可以是一个或多个视频、转录、课堂笔记或现有实操证据；仅修改已有日志格式时无需索要视频。需要从视频抽取但没有可访问素材时，只询问缺少的路径，不重复索要已提供的信息。

同一天的多个视频合并为一个日期条目；材料跨天时按实际日期划分。支持 `.wmv` 等本机工具可解码的格式。来源不足时说明缺口，不编造教学内容、操作、错误或截图。

封面字段优先来自用户提供的信息 / 配置和已有文档。可只读复用本 skill 目录下既有的 `.practicum.env`；新临时配置放任务目录，无需在仓库创建身份文件。只询问交付确实缺少的字段，等待时继续整理材料。不要将配置当作 Shell 脚本执行，不在控制台打印身份信息。

## 按需使用资源

- 需要音视频抽取、运行实操或缺少文档工具时，读 [工具准备](references/prerequisites_and_tooling.md)；不把整张工具清单当作每次启动的门禁。
- 写正文时读 [语言与事实规范](references/humanize_student_tone_guide.md)。
- 创建 / 更新 Word 时读 [文档格式](references/document_format_spec.md)，使用包内 [校标](assets/ecut_logo.png)。有用户模板则优先采用；无需访问项目的 `docs/` 目录。
- 浏览器 / 桌面操作遵循当前用户的工具偏好；Codex 中使用 `cua_repl` 并读取其运行时文档。只有用户选择开源 Cua 且需从 WSL 控制 Windows 原生窗口时，才读 [WSL 参考](references/wsl_cua_host_setup.md)。

## 完成条件

1. 先整理“材料讲了什么、实际完成什么、证据在哪里”。仅当请求包含复现实操或补拍证据时，在隔离目录执行相应任务；不因为材料提到某个组件就部署整套大数据环境。
2. 证据来自真实应用窗口或浏览器视口；交付图片不包含桌面、系统栏或无关窗口，不用文字渲染冒充截图。不自动上传操作回放。
3. 按日期在用户指定的同一主文档追加；同日重跑更新原条目，不重复日期。新建时使用 `生产实习日志_<姓名>.docx`。先在任务目录备份 / 编辑副本，再替换已授权的目标，保留历史日期。
4. 渲染并查看排版，确认图片可读、表格无截断、日期唯一且旧内容保留，再交付文件路径及未完成事项。缺少证据或渲染能力时明确标为草稿，不声称已核验。
