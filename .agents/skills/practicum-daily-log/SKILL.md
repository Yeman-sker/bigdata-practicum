# 生产实习每日日志自动化实操与 Cua 驱动规范 (Practicum Daily Log & Cua Computer-Use)

本规范面向整个生产实习团队（支持 Windows WSL2 与 macOS OrbStack 跨平台）。为确保无 Hermes 环境的组员能够完全无缝复用，**全面禁止使用 Hermes 私有工具（如 `browser_exec` 等）**，统一采用开源 Computer-Use 基础设施 **Cua (`trycua/cua`)** 来驱动真实电脑执行浏览器与终端截图。

---

## 一、 触发前提与输入契约 (Trigger & Input Contract)

本 Skill **必须由组员显式提供视频文件路径**方可启动：

1. **显式输入要求**：
   - 触发时必须包含：**一个或多个视频文件的绝对/相对路径**（例如：上午录屏 + 下午录屏）。
   - **缺失阻断**：若用户仅发出“写今天日志”而未提供任何视频路径，Agent **必须立刻停下主动索取**：“请提供今天教学录屏的文件路径（支持一个或多个视频文件，直接输入路径即可）”。
2. **视频格式特征 (.wmv 官方格式)**：
   - 教师发布的视频格式主要为 Windows 平台的 **`.wmv`** 格式（同时也兼容 `.mp4`, `.flv`, `.mkv` 等）。
   - `ffmpeg` 对 `.wmv`（WMV1/WMV2/WMV3/WVC1 视频流与 WMA2 音频流）具备原生高效解码能力。
3. **多视频处理策略**：
   - 若用户传入多个视频（如 `morning.wmv` 与 `afternoon.wmv`），Agent 依次提取各视频音频或进行轻量合并，**统一综合提炼为当天的同一篇实习日志条目**，不可拆成多个天数。

## 三、 大学生实训语言风格与去 AI 味原则

严格遵循 `references/humanize_student_tone_guide.md`（深度融合 `petergyang/no-ai-slop` 核心经验）：
- **执行两大黄金测试 (The Golden Tests)**：
  1. **可移植性检验 (The Portability Test)**：凡是能原封不动套在别门课程、别的学生身上的假大空套话（如“深刻理解了架构思想”、“提高了工程素养”）一律删除，强制替换为本堂课特定的命令、参数、报错或配置；
  2. **事实说话 (Show, Don't Tell)**：禁止用形容词教老师怎么想（不写“至关重要”），直接陈述具体动作与因果后果；
- **坚决剔除伪深刻结尾与伴随从句**：禁止在结尾强行升华上价值（“这不仅是……更是……”），严禁以虚浮的伴随句结尾，以最朴素的下一项具体操作收尾；
- **标准五板块排布**：单日条目紧凑控制在 200~300 字，按【今日学习与任务】、【动手操作过程】、【遇到的小问题与解决】、【实操结果截图】、【今日心得】分段呈现。

## 四、 核心技术标准与身份认证机制

### 1. Stage 0：身份检测与组员主动引导 (Identity Onboarding)
为保证组员 clone 代码库后能独立运行且互不污染，实行**Skill 内部身份环境变量隔离**：
- **检测门禁**：Agent 接收到日志生成指令时，首先检查 Skill 目录下是否存在 `.practicum.env`（路径：`.agents/skills/practicum-daily-log/.practicum.env`）。
- **主动交互式问询（若缺失）**：
  - Agent 主动停下发起询问：“你好！检测到这是首次在本机生成实习日志，为了确保文档封面、表头和第一人称符合你的真实信息，请告诉我你的：\n1. 姓名\n2. 学号\n3. 班级（默认 2326903）\n4. 当前开发环境（WSL2 还是 OrbStack）”。
  - 收到组员回复后，Agent 自动基于本 Skill 目录下的 `.practicum.env.example` 渲染并生成本地专属的 `.practicum.env` 文件。
- **隐私与仓库保护**：
  - `.practicum.env` 已在 `.gitignore` 中声明（全局忽略），严禁提交到远程 Git 仓库，避免组员个人隐私泄露及代码冲突。
  - 后续所有 Word 文件命名（`docs/生产实习日志_${PRACTICUM_STUDENT_NAME}.docx`）、封面字段、表头信息及正文人称，均动态绑定读取自该配置文件。

### 2. 环境安装确认闸门 (Explicit Confirmation Gate - 硬性规则)
**严禁 Agent 在组员电脑上静默自动安装任何系统软件或包**。在检测到环境缺失工具时，必须停下向组员发出显式确认：
- **触发场景**：自检发现缺少 `ffmpeg`、`cua-driver`、`python-docx` 等必要工具时。
- **确认流程规范**：
  1. 列出缺失的具体工具名称与用途；
  2. 给出拟执行的安装命令（如 `pip install cua-driver python-docx` 或 `brew install ffmpeg`）；
  3. **主动向组员发问征询**：“检测到当前环境缺少上述必要工具，请问是否允许我为您自动执行安装？（您也可以选择自行在终端执行上述命令后再继续，输入 y 确认 / n 拒绝）”；
  4. **只有在组员明确回复同意（如 y / 是 / 允许）后，方可调用命令执行安装**；若组员未同意或要求自己装，Agent 必须等待，绝不强行越权。

### 3. 代码库共享与宿主机原生开发架构 (Single Repo Sharing)
为彻底避免远程连接虚拟机的繁琐与延迟，**整个实训体系仅共享当前 Git 代码库 (`bigdata-practicum`)**：
- **边界隔离原则**：
  - **共享范围**：仅此工程目录（代码、配置模板、实训文档、每日日志、Cua 截图）。
  - **虚拟机本地**：Hadoop 运行组件（`/opt/soft`）、底座数据存储（`/data/hadoop`）、MySQL 数据与元数据、SSH 秘钥坚决保留在 Linux 内部本地，严禁跨盘共享，彻底绝收权限（POSIX 777）与性能崩溃风险。
- **宿主机原生体验**：
  - 在宿主机（macOS / Windows）直接用原生 VSCode 打开当前项目，无缝编写代码、调试脚本与管理 Git。
  - Cua 直接在宿主机聚焦 VSCode 截取纯原生、高清晰度的代码片段（免去远程桌面/SSH 延迟与字体模糊）。
  - 虚拟机通过挂载/共享路径仅读取代码并执行大数据运算任务。

### 4. 计算机界面交互与单窗口截图规范 (Window-Only GUI Capture)
所有针对宿主机桌面（浏览器 Web UI、活动终端输出、VSCode 代码片段）的截图存证操作，**严格遵循「独立应用单窗口截图」铁律，严禁截取整张桌面全屏**：
- **禁止全屏截图**：严禁将桌面壁纸、macOS 顶部系统菜单栏、底部 Dock 栏或 Windows 任务栏等无关外部元素截入日志，避免文档版面发虚、字体缩小及个人桌面信息泄露；
- **独立单窗口纯净截图 (Window-Only)**：
  - **终端实操存证**：推荐使用现代化 GPU 渲染终端 **Ghostty**（macOS/Linux）或 Windows Terminal。截图必须为终端独立单窗口，完整包含输入的命令提示符与全部输出字符；
  - **Web UI 界面存证**：使用 **Google Chrome / Edge** 独立浏览器窗口，直达目标端口（如 HDFS `localhost:9870` 或 YARN `8088`）并仅截取浏览器自身视口；
  - **代码片段存证**：聚焦在 **VSCode** 独立编辑器窗口中截取核心类与配置；
- **截屏技术通道**：
  - macOS 宿主机：通过 Quartz 获取目标应用窗口的 Window ID，调用系统原生 `screencapture -l <window_id> -o` 实现零背景像素级纯净截屏；
  - Windows 宿主机：使用 Cua (`trycua/cua`) 针对活动应用句柄进行窗口级捕获；
- **大报告双轨规范**：每日日志中配图证明实操，但在最终实习大报告正文中同步保持纯文本等宽排版，避免违反“代码不能截图”的评分红线。

## 六、 实习日志编写与排版硬性规范 (严格对齐实习日志.doc)

严格按照 `docs/templates/实习日志.doc` 的格式与排版要求执行：

### 1. 首页封面硬性规范
* **顶部校标**：居中嵌入东华理工大学标准组合 Logo（引用本 Skill 资源 `assets/ecut_logo.png`）。
* **主标题**：居中大号黑体加粗——**《生产实习》报告**。
* **基本信息字段**（四号宋体，加粗，**严格从 `.practicum.env` 动态读取注入**）：
  * **题    目：** `${PRACTICUM_TOPIC}`
  * **学　　号：** `${PRACTICUM_STUDENT_ID}`
  * **姓　　名：** `${PRACTICUM_STUDENT_NAME}`
  * **专    业：** `${PRACTICUM_MAJOR}`
  * **班    级：** `${PRACTICUM_CLASS}`
  * **企业指导教师：** `${PRACTICUM_ENTERPRISE_MENTOR}（${PRACTICUM_ENTERPRISE_NAME}）`
  * **学校指导教师：** `${PRACTICUM_SCHOOL_MENTORS}`
  * **实习时间：** `${PRACTICUM_START_DATE}——${PRACTICUM_END_DATE}`
* **底部日期**：居中偏右——当前归档年月（如：`2026年09月`）。

### 2. 结构精简铁律 (严禁将模板说明写入正文)
* **说明文字剔除**：原始模板中的“实习报告撰写提纲”与“实习报告格式要求”仅为给学生参考的**元规范（Meta Guidance）**，**严禁将这两大段说明文字打印或写入正式提交的日志文档中**！
* **页面衔接**：封面页后插入分页符，**直接且立即进入《实习日志》主体表格**，杜绝任何中间冗余页面。

### 3. 页面与排版样式硬指标
* **页面边距**：上下边距 `2.54cm`，左边距 `3.00cm`，右边距 `2.00cm`。
* **字体规范**：
  * 一级标题：常用四号宋体，加粗；
  * 二级及以下标题：小四号宋体，加粗；
  * 正文：小四号宋体；
  * 非汉字字符（英文、数字及代码）：**Times New Roman** 字体。
* **段落与间距**：
  * 行距：严格设为 **1.25 倍行距**。
  * 缩进：正文段落**首行缩进 2 个汉字字符**。
* **目录与文献**：
  * 目录自动生成；
  * 参考文献遵循国家标准 **GB/T 7714**。

### 4. 表格循环单元结构 (单日条目)
日志表格由单列交替行构成，每天占两行单元格：
- **行 1（窄行）**：`日期：YYYY年MM月DD日`
- **行 2（内容行）**：`实习记录:`
  - 首行缩进 2 字符，包含今日实训任务与目标、实操配置与执行过程、遇到的问题与解决、成果展示（Cua 抓取的高清 Web UI / 终端截图）、今日总结。

### 5. 交付与更新逻辑 (唯一单文档连续追加)
* **全局唯一文档原则**：
  - **严禁**每天分散创建独立的 Word 文件（如不要创建 `0907.docx`, `0908.docx` 等）。
  - 全周期**永远维护且仅维护唯一的一份 Word 主文档**：`docs/生产实习日志_${PRACTICUM_STUDENT_NAME}.docx`。
* **增量追加与状态维护**：
  - 第一天初始化：由模板生成，写入封面、表头固定档案，填充 Day 1 的日期、记录与 Cua 截图。
  - 后续每天自动化：**直接就地打开该唯一文档**，定位到下一个空闲单元格（若模板原有的 4 个预置格子已填满，则自动在表格末尾追加新的“日期行”与“实习记录行”），填入当天内容并就地保存。
  - **幂等性防护**：若同一日期重复执行，自动覆盖更新当天单元格，绝不产生重复的同名日期行。
  - Markdown 留底：同步在 `docs/daily-logs/` 下按天留存，但提交物始终只有这份唯一的完整 Word 文档。
